# 未成年人AI陪伴干预

界定未成年人AI陪伴中的授权、风险信号和人工关怀。

## 领域资料

`contracts/context.schema.json` 定义共享资料格式，`fixtures/context.json` 提供可公开使用的虚构样例。领域资料按版本保存参与者、事实与约束，代码中的读取器负责检查必要字段。

当前资料反映以下业务事实：

- 部分未成年人更愿意与AI聊天
- AI陪伴可能形成依赖并削弱现实关系处理
- 真实情感创伤仍需由现实中的人承接

## 治理后台（`src/governance/`）

面向学校侧的治理后台：把学生从“只向AI倾诉”的状态，按等级、有依据地接到真实的人身边。后台**不保存任何对话原文**——原文只在陪伴端边界脱敏后即被丢弃。

### 需求 → 模块映射

| 需求 | 实现 |
| --- | --- |
| 脱敏会话信号 | `redaction.py`：原文不进后台；手机号/身份证/邮箱/QQ/地址/自报姓名脱敏；假名派生 |
| 监护授权、年龄、服务时段、模型版本登记 | `registry.py` + `models.py`：3-17岁、授权有效期、夜间窗口、模型版本登记与退役 |
| 风险规则与最小化摘要 | `rules.py`：版本化规则集（`fixtures/rules_v1/v2.json`），每次评估输出等级+命中规则+人话理由 |
| 普通波动只留去标识化趋势 | `retention.py` `TrendStore`：0级只进「学年周×年龄段×等级」聚合，明细不落盘 |
| 持续孤立/自伤暗示/现实伤害分级交给有资质人员 | `escalation.py`：1/2/3级派单与SLA（3天/24小时/15分钟），`HumanContact` 强制真实人际接触闭环 |
| 自动判断说明依据、允许人工否决 | `Assessment.explain()`；`override_case` 必须给理由，原评估保留、否决留批注 |
| 消息重试不重复发出紧急联络 | `RecordingNotifier` 去重键 + `retry_emergency_contact` 幂等补偿 |
| 授权撤回 / 跨校转介 / 规则换版 / 夜间值守 / 到期删除留可核验证明 | `audit.py` 哈希链 + 证书（签发点链前缀校验）；`backend.py` 五类动作均写审计并签证书 |
| 学生明确谁可见哪些信息 | `views.py` `StudentView.visibility()` 可见性总表 |
| 家长只收到必要的安全结论 | `GuardianView` 只列实际送达的结论；2级结论在有资质人员接单审核后才发出 |
| 专业人员审查升级是否及时完成真实人际接力 | `ProfessionalView.case_review()`：依据、时间线、SLA、接触渠道（禁止 ai_chat） |

### 关键设计决策

- **通知时序**：3级（迫在眉睫伤害）紧急联络立即发出，生命安全优先；2级（自伤暗示）的监护人结论推迟到有资质人员接单审核之后——专业人员可以先否决，否决则监护人什么都收不到。
- **持续类规则的隐私形态**：孤立天数在陪伴端本地统计，只有跨阈值的那一条信号携带 `isolation_days_3+` 特征上传，窗口明细永不出设备。
- **撤回即停**：授权撤回后该学生信号即刻被拒绝处理，留存明细立即删除，全过程出证。

### 本地校验

```bash
python -m unittest discover -s tests -v   # 26个测试覆盖上述每条承诺
python -m examples.walkthrough            # 端到端走查（虚构学校样例）
```

运行项目自带测试可确认样例资料能够读取，且领域标识、版本和事实记录完整。样例不含真实个人信息、账号、密钥或连接凭据。
